## 1. 为什么这样抄不算抄

Codédex 值得学的是**模式**，模式不受版权保护；受保护的是它的**内容与标识**。

| 层 | 做法 |
|---|---|
| 布局、导航、交互逻辑 | 借鉴模式 ✅ |
| 像素风 UI 框架 | **用它自己用的那个开源框架**（NES.css，MIT） ✅ |
| 像素字体 | 用同款开源字体（Press Start 2P，OFL） ✅ |
| Logo、角色美术、专属字体 | **不用**，全部原创或 CC0 ❌ |
| 课程正文 | **不用它的**，改编自 CC BY 4.0 的中文教程 ❌ |

直接搬源站的课程内容没有任何收益 —— 详见第 2 节。

### 2.3 「先通读」模式

源仓库自己有一个互动版站点 `learn-py.org`。我们**保留它的「先通读」入口**（决策 8）：每一关左下角有一个「📖 对照原文」按钮，点开是源教程该章节的完整长文。

- 作用：想深挖某个概念时，一篇长文比碎片化讲解有用
- 实现：不内联正文（不复制），而是**外链**到源站对应章节
- 好处：既不复制内容，又给了「想认真读」的出口

### 2.4 改编 = 切碎

**这是整个项目的成败关键，也是「不无聊」的真正来源。**

源教程一章 = 7 道题、约 35 分钟、大段叙述。Codédex 一关 = 读 1 分钟 + 写代码 + 立刻反馈。

> **原则：宁可多切几关，绝不留长讲解。**
> 一章拆成 4-8 关，每关只有「一屏讲解（3-5 句）+ 一道题」。

例：源教程把 `if` 用 2000 字一次讲完 → 我们拆成 7 关：

```
19 如果……  →  20 否则  →  21 多条岔路  →  22 比大小
→  23 一起判断  →  24 隐式的真假  →  25 🏆 垃圾分类员
```

每一关都能立刻动手，所以停不下来。**搬运长文反而要花更多时间删改，且必然偏离目标文体。**

判分用例：源教程没有 → 全部由我逐题编写。

### 3.2 题型轮换（6 种）

相邻两关**必须换题型**，这是对抗单调的主要手段。

| 题型 | 说明 | 判分方式 |
|---|---|---|
| 照着写 | 给明确指令，照做 | 输出比对 |
| 补全填空 | 骨架已给，填 `____` | 输出比对 |
| 预测输出 | 先选答案，再真跑验证 | 选项比对 |
| **找 bug** | 给能跑但逻辑错的代码 | 输出比对 |
| 从零写 | 给需求自己写 | 输出 + 变量比对 |
| 自由创作 | 答案不唯一 | 只检查函数行为 |

> **找 bug** 是最有价值的新增题型（源站和 Codédex 都没有）：真实工作 80% 时间在找 bug，不是从零写。

## 4. 单关内部流程

```
0:00  进入          顶部：第 19 关 · 10 XP
0:05  一屏讲解       3-5 句话
0:40  可折叠示例     想看才展开
1:00  进入练习       编辑器亮起
1:30  写代码
2:00  点「运行」     免费、无限次、不判分
3:00  点「提交」     判分
3:02  通过 → +10 XP 飘字 + 音效 + 卡片翻出
3:05  地图更新       节点点亮、长出装饰、下一关解锁
```

**「运行」和「提交」分开，是这个模式的核心。** 运行 = 我自己试试（无压力）；提交 = 判分。这个区分让人敢乱试。

### 4.1 界面构成

- **顶栏**：Logo / 面包屑（岛屿区域 / 关卡名）/ 区域进度条 / 设置
- **左栏**：讲解（标题、正文、代码示例、任务卡、帮助按钮组）
- **右栏上**：编辑器（文件名、行号、语法高亮）
- **右栏中**：工具栏（`▶ 运行` / `✓ 提交`）
- **右栏下**：终端（真实输出）
- **底栏**：关卡名 + 进度（第 2/7 关）+ XP + `返回` / `下一关`

### 4.2 判分反馈（四种情况）

| 情况 | 反馈 |
|---|---|
| 全过 | 通过 + XP + 卡片 |
| 部分过 | 「测试 2 没过：应该是 `30`，你的程序输出 `7`」 |
| 代码报错 | **中文翻译** + 行号 + 建议（「第 3 行变量拼错了，是不是想写 `name`？」） |
| 死循环 | 5 秒中断 + 「检查 `while` 的条件有没有机会变成 False」 |

**失败不扣任何东西**（不扣 XP、不扣次数、不记录）。这是让人敢试错的前提。

### 4.3 帮助系统

| 入口 | 行为 | 代价 |
|---|---|---|
| 💡 提示 | 一句方向性的话 | 卡片降为银 |
| 📖 对照原文 | 外链源教程该章 | 无 |
| 🎬 看讲解 | 走查说明 | 无 |
| 🔓 查看答案 | 二次确认后展开参考解 | 卡片降为灰，仍算通关 |

## 5. 游戏系统

### 5.1 XP 与等级

- 普通关 **10 XP**（32 关），BOSS 关 **30 XP**（6 关）
- 总计 **500 XP**
- 等级 5 档：`Lv.1` 0 / `Lv.2` 100 / `Lv.3` 220 / `Lv.4` 350 / `Lv.5` 500
- 满级触发「岛主」结局画面

### 5.2 卡片（收集物）

每关通关给一张像素卡片，三档成色：

| 成色 | 条件 |
|---|---|
| 🌟 金 | 没用提示、没看答案 |
| ⭐ 银 | 看了提示 |
| ☆ 灰 | 看了答案 |

不惩罚，只影响成色 —— 保留「回头打金牌」的动力。

### 5.3 徽章

每通关一个区域给 1 枚，共 6 枚（本批）。

### 5.4 地图生长

每通一关，地图上长出一个装饰物（篝火 → 帐篷 → 风车 → 桥 → 灯塔 → 城堡）。**回头能看见自己走过的路。**

### 5.5 侧栏进度面板

```
Level   Lv.3
关卡     12 / 38
经验     120 / 500
徽章      2 / 6
```

### 5.6 成就（隐藏，10 个）

「第一次报错」「死循环幸存者」「一次通关」「金卡收藏家」「夜猫子」「回头是岸」（看答案后重打拿金牌）……

### 5.7 音效

通关「叮」、报错「噗」、解锁「咔」。带静音开关，默认开。

### 5.8 明确不做

| 不做 | 原因 |
|---|---|
| 连续打卡 streak | 会变成负罪感 |
| 金币 / 商店 / 皮肤 | 会把注意力从代码转到刷币 |
| 排行榜 | 单人使用无意义 |

## 7. 技术方案

### 7.1 栈

- **React + Vite + TypeScript**，纯前端，无后端
- **Pyodide**（CPython → WebAssembly）在浏览器里真跑 Python
- **Web Worker + 超时中断**：防止 `while True` 卡死页面
- **localStorage** 存进度
- 桌面端优先（决策 9）

### 7.2 为什么 Pyodide

真 CPython、真报错、真 `input()`，离线可用（首次加载约 10MB 运行时，之后浏览器缓存）。不需要服务器，省钱省心。

### 7.3 内容数据结构

```ts
type Lesson = {
  id: string            // "py-19"
  region: string        // "forest"
  title: string         // "如果……"
  type: 'guided' | 'fill' | 'predict' | 'debug' | 'scratch' | 'free'
  xp: number
  video?: string        // 「看讲解」
  content: Block[]      // 讲解段落（3-5 屏）
  source?: {            // 「对照原文」外链
    url: string
    label: string
  }
  exercise: {
    prompt: string
    starterCode: string
    stdin?: string[]    // input() 题型的预置输入
    tests: Test[]       // 判分用例
    hints: string[]
    solution: string
  }
}
```

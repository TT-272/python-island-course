## 2. 课程设计原则（六条，不可违反）

### 2.1 用倒推法定目标
先问"学完能独立写出什么"，再决定教什么语法。第二季的终点是一个**有真链接、别人点开就能用**的网页小工具。

### 2.2 粒度法则：一关 = 一个概念 + 一道题
**这是"不无聊"的唯一来源。** 把 `try / except / else / finally` 塞进一关 = 学员放弃。必须拆：`try/except` 一关、捕获特定异常一关、`raise` 一关。

### 2.3 难度节奏：易 — 易 — 中 — BOSS
每个区块最后一关是 BOSS（综合题，**XP 30**，普通关 **10**）。BOSS 不是变难，是让学员感到"我用前面学的东西做出了一个东西"。

### 2.4 题型轮换
相邻两关必须换题型。六种：

| 题型 id | 名字 | 说明 | 判分方式 |
|---|---|---|---|
| `guided` | 照着写 | 给明确指令，照做 | 输出比对 |
| `fill` | 补全填空 | 骨架已给，填 `____` | 输出比对 |
| `predict` | 预测输出 | 先选答案，再真跑验证 | 选项比对 |
| `debug` | 找 bug | 给能跑但错、或语法错的代码 | 能跑通 + 输出比对 |
| `scratch` | 从零写 | 给需求自己写 | 输出 + 变量比对 |
| `free` | 自由创作 | 答案不唯一 | 只检查函数行为 |

**每个区块至少要有 1 个 `debug` 关。** 理由：真实工作 80% 的时间在找 bug；新手最需要的技能是"看懂报错 → 修好"。

### 2.5 讲解的写法：先说"为什么需要它"，再说"它是什么"
- 反例：「`try` 是异常处理语句，语法是 `try: ... except:`」
- 正例：「你有没有写过一按回车就崩掉的程序？程序崩了，用户就跑了。Python 有个办法让它在出事时不崩。」

### 2.6 判分标准
- 忽略首尾空白，**内容与顺序必须完全一致**
- 全过才通关；部分过要指出**哪个测试没过、期望什么、你给了什么**
- **失败不扣任何东西**（不扣 XP、不扣次数、不记录）

第一季做完后对照 Codédex 官方课程（`codedex-io/python-101`，MIT）发现的三个**能力缺口**。它们不是"语法没教"，而是"练得不够"。

| # | 短板 | 第一季现状 | 第二季在哪补 |
|---|---|---|---|
| 1 | **数值计算** | 只有「体温计」一关是真实计算；Codédex 有 5 关（温度 / BMI / 勾股 / 求根 / 汇率） | 🧪 实验室（pandas 筛选统计、画图）+ 🎓 出师（作品里的真实计算） |

- **第一季已经试点**：第 26 关「垃圾分类员」改成了 26 行的长作业（手写三段判断 + 累计），并在讲解里埋了一句"下一关你会学到省力的办法"—— 让学员先吃没有循环的苦，再学循环。

## 5. 技术约束（★ 最重要，先看这节再动手）

学员的代码**跑在浏览器里的 Pyodide 沙箱**，不是跑在服务器上。这决定了很多东西教不了。

### 5.1 能做 ✅

| 能力 | 说明 |
|---|---|
| 纯 Python 逻辑 | 变量、循环、函数、类、异常、模块 |
| 标准库大部分 | `os` / `datetime` / `math` / `random` / `json` / `csv` / `re` |
| numpy / pandas / matplotlib / scipy / scikit-learn | Pyodide 已编译，可直接 import |
| Pillow（图像） | ✅ |
| beautifulsoup4 / lxml | ✅ |
| pytest / sympy | ✅ |
| micropip 装纯 Python 包 | ✅ 能装 PyPI 上的纯 Python 轮子 |
| requests | ⚠️ 是**补丁版**：底层走浏览器的 fetch |

### 5.2 做不到 ❌

| 做不到 | 原因 |
|---|---|
| **起一个网站给别人访问** | 没有 flask（不在包清单里）；浏览器里也无法对外提供服务 |
| **抓任意网页** | `requests` 受浏览器 **CORS** 限制，只能抓允许跨域的接口 |
| **sqlite3 / openpyxl / pygame** | 不在 Pyodide 包清单里 |
| **让文件真正持久保存在磁盘** | Pyodide 有内存文件系统，关掉页面就没了（要持久化得对接 IndexedDB） |

> **包清单可以现场核实**：`python-island/public/pyodide/pyodide-lock.json` 里有全部 357 个可用包。
> **写涉及第三方库的关卡之前，一定要先去这个文件里查该包在不在。**

### 5.3 网络请求的写法定死

**只用经过实测、满足「支持跨域 + 不需要 key + 稳定」的 API。** 已知可用的：

| API | 用途 | 备注 |
|---|---|---|
| `https://api.open-meteo.com/v1/forecast?latitude=31.23&longitude=121.47&current=temperature_2m` | 天气 | 免 key，支持跨域 |
| `https://restcountries.com/v3.1/name/japan` | 国家信息 | 免 key，支持跨域 |
| `https://api.github.com/repos/python/cpython` | GitHub 公开数据 | 免 key，有速率限制 |

**每个网络关卡动笔前，先把 URL 在浏览器里跑一遍确认还能用。** 跑不通就换 API 或换成非网络题。

### 5.4 发布的现实

第二季末的"发布"只能走 **静态托管**（GitHub Pages）。学员的作品是"单文件 HTML + 从 CDN 拉 Pyodide"，本身就是静态文件。

## 6. 数据结构与判题接口

### 6.1 课程数据

```ts
type Lesson = {
  id: string;            // 'py-41'
  region: string;        // 'dock'
  order: number;
  title: string;
  type: 'guided' | 'fill' | 'predict' | 'debug' | 'scratch' | 'free';
  xp: number;            // 普通 10，BOSS 30
  boss?: boolean;
  content: Block[];      // 讲解
  exercise: {
    prompt: string;                          // 题目正文
    starterCode: string;                     // 编辑器里的起手代码
    stdin?: string;                          // 有 input() 的题要预置输入
    tests: { name: string; code: string }[]; // 判分用例
    hints: string[];                         // 分层提示，从宽到细
    solution: string;                        // 参考解
    bonus?: {                                // BOSS 关的可选进阶题
      prompt: string;
      starterCode: string;
      tests: { name: string; code: string }[];
    };
  };
};

type Block =
  | { t: 'p';      text: string }              // 段落
  | { t: 'code';   lang: 'python'; code: string }
  | { t: 'tip';    text: string };             // 小贴士

type Region = {
  id: string; name: string; icon: string;
  season: 1 | 2; order: number;
  lessons: string[];
  badge: { name: string; sprite: string };
};
```

### 6.2 判题接口

```ts
judge.run(code, { stdin?, tests?, timeoutMs? })
  → { ok, stdout, ms, tests: TestResult[], error?, timedOut? }
```

`ok` 只表示**代码跑通了**，不代表测试全过。全过要看 `tests.every(t => t.passed)`。

### 6.3 写判分用例的规矩（★ 最容易写错的地方）

判分用例是**一段 Python 代码**，在学员代码跑完之后、**同一个命名空间**里执行。

- **可用的变量**：`_stdout`（学员程序的完整输出字符串）、`_code`（学员提交的源码字符串）+ 学员定义的所有变量
- **判分方式**：用 `assert`；**`assert` 的第二个参数就是给学员看的话**
- **好消息**：断言失败时，Python 会把学员的实际值打出来

```python
# 输出类题目（最常用）
assert _stdout.strip() == "你好，冒险者", f"应该输出 你好，冒险者，你的程序输出的是 {_stdout.strip()!r}"

# 多行输出
lines = _stdout.strip().split("\n")
assert len(lines) == 3, f"应该输出 3 行，你输出了 {len(lines)} 行"
assert lines[0] == "我在 Python 岛", f"第一行应该是 我在 Python 岛，你写的是 {lines[0]!r}"

# 检查学员定义的变量
assert 'score' in dir(), "题目要求定义一个叫 score 的变量"
assert score == 75, f"score 应该是 75，你写的是 {score!r}"

# 检查函数行为
assert greet("小明") == "你好，小明", f"greet('小明') 应该返回 你好，小明，实际返回 {greet('小明')!r}"
```

**有 `input()` 的题目必须给 `stdin` 字段**，值是喂给 `input()` 的内容（多行用 `\n` 分隔）：

```ts
stdin: "小明\n",
```

没用提示且没看答案 = **金**；看过提示 = **银**；看过答案 = **灰**。**不惩罚，只影响成色。**

## 8. 一关完整样例（照这个格式写）

以第一季第 3 关为格式范本 —— 它演示了 `debug` 题型和"提前建立报错循环"的设计意图。

**引号的故事** · `debug` · 10 XP

**讲解（4 句）**
> 下面这段代码是**故意写坏的**。
> 引号没闭合，是新手最常见的错误 —— 你以后一定会遇到很多次。
> 好消息是：Python 会明确告诉你**错在第几行**。
> 你的任务不是重写，是**把它修好**。

**起手代码（故意是坏的）**
```python
print("Python 很好玩)
```

**题目**：这行代码跑不起来。修好它，让它打印出 `Python 很好玩`

**提示**
1. 数一数这一行的引号，是不是少了一个
2. 引号必须成对：开头一个，结尾一个

**参考解**
```python
print("Python 很好玩")
```

**判分用例**
```ts
tests: [
  { name: '代码能跑通',            code: `assert True` },
  { name: '输出内容正确',          code: `assert _stdout.strip() == "Python 很好玩", f"应该输出 Python 很好玩，你的程序输出的是 {_stdout.strip()!r}"` },
]
```

> **设计意图**：这一关的价值不在"学会写 print"，而在**让学员第一次走完「代码报错 → 读懂 → 修好」这个循环**。这个循环是整个学习过程中最重要的一件事。

## 二、发现并修复的问题

### 1. 工坊的 BOSS 根本没用循环（最严重）

**现象**：第 34 关「猜数字前传」是工坊（循环区）的 BOSS，但它的实现是"猜一次就结束"，**没有用到本区教的 `for` / `while`** —— 一个循环区的毕业题不用循环，等于没综合到本区的东西。

**还带出一句错话**：讲解里写着"要让它一直猜到对，得等到熔炉学了函数，把整段打包起来"。这句有两个错：
- 让循环"一直猜到对"靠的是 `while`，跟函数没关系；
- 结业作品（第 40 关）也**没有**用 `def`。

**修法**：把第 34 关重写成 **for 循环猜 3 次**（秘密数字写死成 4，固定喂 2、6、4 三次猜测）。
这样既让 BOSS 真的用上本区的循环，又把「前传 / 结业」的关系做实了：
- 第 34 关：`for` 猜 3 次，猜完就结束
- 第 40 关：`while` 一直猜到对

判分也跟着改成三条：两次提示都对（含顺序）、最后猜中了、**一共给了三次提示**（这条能抓住"循环没跑够次数"的写法）。

### 2. 第 28 关说"以后要学的字典"，但字典早就学过了

第 28 关（工坊）的提示写着"列表、字符串、还有**以后要学的**字典，都能被 for 遍历"。可是字典是第 17 关（仓库镇）就教过的。

**修法**：改成"还有**你学过的**字典"。

### 3. 第 39 关引错了关卡

第 39 关说"**上一关**那个 double 函数只有两行"。但上一关是第 38 关（传值的秘密），它定义的是 `add_one` / `add_item`；`double` 是**第 37 关**写的。

**修法**：改成"**第 37 关写的**那个 double 函数"。

### 4. 第 7 关的起手代码一运行就崩

第 7 关是"补全填空"，起手代码是 `print(len())` —— 一运行直接 `TypeError`。而其他四个补全填空关（13 / 28 / 36 / 39）都是**能跑、但结果是错的**，学员看到的应该是"结果不对"，不是"程序炸了"。

**修法**：改成 `print(len(""))`（量了个空字符串，输出 0），判分信息就变成正常的"应该输出 3，你的程序输出的是 `'0'`"。

## 五、已知限制（不算 bug，但要知道）

1. **判分只看输出和变量，不看源码** —— 所以没法验证"你是不是真的用了 `if`"。理论上学员可以直接 `print("可以进场")` 蒙过去。这是个自学工具，没有防作弊的必要；个别关卡用"把结果装进指定变量再检查"来补强。
2. **`predict`（预测输出）类关卡没法强制"先猜"** —— 判分只能比对最终输出，学员完全可以边运行边看。关卡文案里写了"先猜再运行"，但那靠自觉。
3. **`input()` 的提示语不换行** —— 浏览器里没有终端回显，所以"猜一个数字：小了"会挤在一行。已在这几关的讲解里说明，并给了替代写法。
4. **列表输出用的是 Python 自己的格式**（`['稻香', '夜曲']`），学员写 `print(列表)` 就能得到，不需要自己敲标点 —— 但如果学员改成逐个打印，判分就会不过。
5. **随机数关的判分绕开了随机性** —— 要么检查取值范围（第 33 关），要么把秘密数字写死（第 34、40 关）。学员自己玩的时候要手动换成 `random.randint`。
6. **Pyodide 不支持 flask / django / sqlite3 / openpyxl / pygame**；`requests` 受 CORS 限制。第二季写内容时要避开。

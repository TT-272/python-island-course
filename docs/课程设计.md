## 二、设计原则

1. **倒推法定目标**：终点是结业作品（猜数字游戏）。倒推它需要什么零件 —— `random` / `while` / `if-elif` / `input` / `int()` / 变量 / `print`，这些必须在前面的关卡全部覆盖到。
2. **粒度法则：一关 = 一个概念 + 一道题**。把 `if / elif / else` 塞进一关，学员第 5 关就放弃了。
3. **难度节奏：易 — 易 — 中 — BOSS**。每个区末尾一个 BOSS（综合题，XP 三倍）。BOSS 不是变难，是让学员感到"我用前面学的东西做出了一个东西"。
4. **题型轮换**：相邻两关必须换题型。
5. **讲解先说"为什么需要它"，再说"它是什么"**。反例：`if` 是条件语句，语法是……；正例：你每天都在做判断：如果下雨就带伞。
6. **失败不扣任何东西**。不扣 XP、不扣次数、不记录。

### 六种题型

| 代号 | 界面显示 | 做什么 |
|---|---|---|
| `guided` | 照着写 | 讲解里给范式，学员照着敲 |
| `fill` | 补全填空 | 起手代码留一个洞，填上就通 |
| `predict` | 预测输出 | 先自己猜结果，再写代码验证 |
| `debug` | **找 bug** | 给一段坏代码，修好它 |
| `scratch` | 从零写 | 只给需求，自己搭 |
| `free` | 自由创作 | 综合题，只给目标 |

> `找 bug` 是这个项目自己加的题型（Codédex 和源教程都没有）。理由：真实工作里大半时间在找 bug，而新手最需要的技能是"看懂报错"。
> **所有找 bug 关都带 `bugSpot` 标记**：题目区会把起手代码整段摆出来，并用红框圈出出问题的那一小段，下面配一句红字说明现象。

## 四、判分约定

- **忽略首尾空白，内容与顺序必须完全一致。**
- 判分失败要指出**哪个测试没过、期望什么、你给了什么**，格式统一为"应该 XXX，你的程序输出的是 YYY"。
- 判分用例是**一段在学员命名空间里执行的 Python 代码**，能读三样东西：学员定义的变量（`secret`、`bag`…）、捕获到的输出（`_stdout`）、以及**学员提交的源码**（`_code`）。
- **一关一题**；BOSS 关另加一道可选的「⭐ 进阶挑战」，做完记金卡。
- 参考解可以配**另一种写法**（`altSolution` 字段）—— 让学员看到"同一个目标的不同路子"。写法二不参与判分，只是展示。
- 卡片成色：不碰提示通关 = 金；看过提示 = 银；看过答案 = 灰。**失败不扣任何东西。**

### 三个特殊情况的处理

| 情况 | 处理 |
|---|---|
| **`input()` 关** | 每关固定 `stdin`，运行时系统自动"替你回答"。断言一律用 `.endswith()`，因为 `input()` 的提示语**不换行**，提示语和输出会挤在同一行 |
| **随机数关** | 不比对具体数值。py-33 检查"每一行都是 1~6 的整数"；py-34 / py-40 把秘密数字**先写死**，跑通后再让学员自己换成 `random.randint` |
| **集合关** | 集合没有固定顺序，不能直接打印。改用 `len(set(...))` 和 `sorted(set(...))`，输出才确定 |
| **要求指定写法的关** | 判分能读 `_code`，所以可以要求"这一关必须用 f-string / 切片 / `pop()`"。检查方式是**文本匹配**（不是语法分析），目的是提醒你动手，不是防作弊 |

## 六、技术约束（写内容前必须知道）

Pyodide 里能用的东西是有限的，357 个包，清单在 `python-island/public/pyodide/pyodide-lock.json`。

**能跑**：numpy / pandas / matplotlib / scipy / scikit-learn / Pillow / beautifulsoup4 / pytest / sympy / micropip
**不能跑**：flask、django、sqlite3、openpyxl、pygame
**受限**：`requests` 是补丁版，受浏览器 CORS 限制，只能抓允许跨域的接口

其他限制：

- 发布只能走**静态托管**（GitHub Pages），站内无法 `git push`。
- 浏览器里**没有终端回显**，所以 `input("提示语")` 的提示语和用户输入会挤在同一行。关卡讲解里已就此给了替代写法（先 `print` 提问，再用不填参数的 `input()`）。
- 判分能读源码（`_code`），但检查是**文本匹配**，不是语法分析：在注释里写个 `%` 也会被判为"用过了"。这个精度是故意的 —— 目的是提醒你动手，不是防作弊。
